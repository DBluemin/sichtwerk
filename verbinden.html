Beispiel-Domain eingeben — z. B. example.com oder Ihre eigene Website
Es werden nur öffentlich erreichbare Seiten gelesen. Nichts wird an der Ziel-Website verändert — Ausspielung erfordert im Produkt Domain-Verifizierung + Konnektor.
Die Analyse-API läuft nur mit dem lokalen Server (GitHub Pages kann nicht crawlen). Lokal starten: cd ~/seo-os && node server.js → dann http://localhost:8899/verbinden.html öffnen.

Aktiv 1 · Analyse ohne Zugriff
Öffentliches Crawling wie hier. Findet Probleme, generiert Vorschläge — ausspielen kann es nichts. Der Einstieg für jede Beispiel-Domain.
Plugin fertig 2 · CMS-Konnektor
Nach Domain-Verifizierung verbindet sich das Cockpit per API mit dem CMS. Für WordPress (der Agentur-Standardfall) liegt der Konnektor als installierbares Plugin bereit: nennwert-seo-connector.php ↓ — Agentur installiert, Site-Schlüssel eintragen, fertig. Jede Maßnahme wird als echte Revision geschrieben, rückholbar.
Produkt 3 · Edge-Layer
Für Systeme ohne CMS-Zugriff: Ein Proxy/Worker injiziert Meta, Schema und Links at-request-time. Fallback — Standard bleibt die echte CMS-Revision.
